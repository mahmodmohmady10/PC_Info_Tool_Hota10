# PC Info Tool 2.0 — Phase 7 (Reports & Release Preparation)

تطبيق سطح مكتب لويندوز 10/11 لجمع معلومات الجهاز ومراقبته وتشخيصه واختبار أدائه، مع إنشاء تقارير محلية. الملف الأصلي `pc_info_tool1.py` لم يتم تعديله.

## الوظائف الحالية
- جمع معلومات الجهاز والمعالج والذاكرة والرسوميات واللوحة الأم والتخزين والبطارية ونظام التشغيل.
- مراقبة مباشرة لاستخدام CPU وRAM وقرص النظام وحركة الشبكة.
- تشخيص أولي للمعالج والذاكرة ومساحة قرص النظام والحالة التي يبلغ عنها Windows للأقراص ومحولات الشبكة والبطارية.
- اختبارات أداء قصيرة ومحدودة للمعالج والذاكرة والقرص.
- حفظ آخر 200 نتيجة اختبار محلياً، وعرض السجل وتصديره إلى CSV.
- إنشاء تقرير HTML عربي قابل للفتح والطباعة، وتقرير JSON تقني.
- واجهة عربية مع الوضع الداكن والفاتح.
- إخراج تقرير معلومات العتاد بصيغة JSON عبر CLI.

## المتطلبات
- Windows 10 أو Windows 11، وPython 3.10 أو أحدث.
- التبعيات: `psutil` و`customtkinter`.

## التشغيل لأول مرة
من داخل مجلد المشروع افتح PowerShell أو CMD وشغّل:

```powershell
py -m pip install -r requirements.txt
py main.py
```

أو شغّل `install_and_run.bat` لتثبيت التبعيات وتشغيل التطبيق على Windows.

## تقرير JSON من سطر الأوامر

```powershell
py main.py --cli
```

## التقارير
من القائمة الجانبية افتح «التقارير» ثم اختر:
- **HTML:** تقرير عربي منسق يتضمن ملخص التشخيص، تفاصيل العتاد، وآخر 50 نتيجة أداء. يمكن فتحه في المتصفح وطباعته أو حفظه PDF من نافذة الطباعة.
- **JSON:** بيانات منظمة تشمل معلومات العتاد، التشخيص، وسجل الأداء المحفوظ (حتى 200 نتيجة).

يُعاد جمع المعلومات عند إنشاء التقرير. قد تستغرق العملية عدة ثوانٍ، وتعمل في الخلفية حتى لا تتجمد الواجهة.

## حدود القياس والتشخيص
- حمل CPU في التشخيص عينة قصيرة مدتها 0.7 ثانية؛ ليست اختبار ضغط.
- RAM يستخدم بيانات الذاكرة الافتراضية المتاحة من النظام.
- مساحة القرص تقيس قسم Windows فقط.
- حالة الأقراص تستخدم `Win32_DiskDrive.Status` من Windows CIM. ليست قراءة SMART كاملة ولا ضماناً لسلامة SSD/HDD.
- فحص الشبكة يتحقق من وجود محول نشط فقط، ولا يثبت الوصول إلى الإنترنت.
- فحص البطارية لا يقيس صحتها الكيميائية أو تآكلها.
- اختبار CPU حسابي قصير، واختبار الذاكرة يستخدم مخزناً مؤقتاً بحجم 16MB، واختبار القرص يقرأ ويكتب ملفاً مؤقتاً بحجم 8MB ثم يحذفه.
- نتائج الأداء تقريبية وتتأثر بالطاقة والبرامج المفتوحة ونوع المكونات؛ قارن الجهاز بنفسه وفي ظروف متقاربة فقط.
- لا تتضمن هذه النسخة مراقبة درجات الحرارة بناءً على طلب المستخدم.
- لا يجري التطبيق تعديلات على النظام أو اختبارات ضغط طويلة.

## الخصوصية
- سجل الأداء والتقارير يُحفظان محلياً في المكان الذي يختاره المستخدم أو مجلد بيانات التطبيق.
- لا توجد عملية إرسال تلقائي إلى خادم خارجي.
- التقرير قد يحتوي على أسماء مكونات الجهاز ومعلومات نظامه؛ راجعه قبل مشاركته.

## الملفات المهمة
- `main.py`: واجهة التطبيق وتوجيه الصفحات.
- `hardware/`: جمع معلومات العتاد.
- `monitoring/`: قراءات المراقبة المباشرة.
- `diagnostics.py`: فحوصات التشخيص.
- `benchmarking.py`: اختبار الأداء وسجل النتائج.
- `reports.py`: إنشاء تقارير HTML وJSON.

## الحالة التراكمية
- Phase 1: مجمعات معلومات العتاد وCLI JSON.
- Phase 2: واجهة GUI عربية ولوحة التحكم وصفحة العتاد والمظهر الداكن/الفاتح.
- Phase 3: مراقبة CPU/RAM/قرص النظام والشبكة.
- Phase 4: ملغاة — حُذفت ميزة الحرارة.
- Phase 5: التشخيص الأولي.
- Phase 6: اختبار الأداء والسجل وتصدير CSV.
- Phase 7: التقارير HTML/JSON وتجهيز التشغيل والتوثيق.

## التحقق
تم فحص صياغة ملفات Python، وتجربة إنشاء تقرير HTML وJSON والتحقق من بنيتهما في بيئة البناء. يلزم اختبار الواجهة والتقارير على Windows لدى المستخدم قبل اعتبار حزمة الإصدار النهائي معتمدة.


## بناء نسخة Windows EXE
- افتح مجلد المشروع على Windows 10/11 (64-bit).
- ثبّت Python 3.10 أو أحدث (64-bit).
- شغّل `build_exe.bat`.
- بعد نجاح البناء شغّل `dist/PCInfoTool2/PCInfoTool2.exe`.
- للتوزيع انسخ مجلد `dist/PCInfoTool2` كاملاً، وليس ملف EXE وحده.
- راجع `BUILD_EXE_GUIDE.md` للاختبار وحل المشكلات.

**الحالة:** ملفات البناء جاهزة. لم يُبنَ EXE النهائي داخل بيئة Linux الحالية؛ يلزم تنفيذ البناء واختباره على Windows.
